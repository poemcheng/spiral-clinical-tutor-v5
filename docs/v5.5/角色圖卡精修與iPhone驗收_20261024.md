# v5.5.1 圖卡臉髮精修、原地決策與 iPhone 驗收

本機主程式版本 5.5.1；公開 v5.5.0 歷史發行保持原樣。此更新以本機主機與同 Wi-Fi 使用為範圍。

## 角色與圖卡對應

13 位角色依各自提供的圖卡進行本機臉部特徵定位與立體頭部變形。參考圖的臉部外觀烘焙至曲面人體皮膚 UV，髮型以對應圖卡的輪廓及顏色建立有厚度、封閉且隨頭骨移動的網格，以圓弧後腦髮型銜接前側輪廓，長髮範圍依圖卡推定。骨架、眨眼、下顎與五種嘴型仍可使用。眼鏡角色另依參考眼鏡輪廓建立立體鏡框。

這是單張圖卡參考的立體重建，側面與背面未提供的細節由模型推定；不宣稱照片級一模一樣或已經使用者外觀驗收。模型採 `data/characters/card-matched-v3/`；圖卡原檔保留且有 SHA256。重建工具 `tools/rebuild_card_avatars.py` 使用本機 Blender、MediaPipe 與 OpenCV，不上傳圖卡；需先準備 Blender / MPFB、人體素材與臉部 landmark 模型。建模腳本失敗會回傳非零狀態。建模預設輸出至獨立的 `runtime/card-avatar-candidate/`，檢查圖像後，執行 `python tools/activate_card_avatars.py --check-only` 核對，再執行 `python tools/activate_card_avatars.py` 備份及套用；不會在重建途中替換使用中的模型。

## 決策後保留位置

「確認此決策」只更新該題的已保存回饋，不重新建立整個情境頁、角色、麥克風或交接表單。若新增安全補強提醒，依原題的位置調整捲動，保持閱讀中的題目。

隔離資料庫中以真實瀏覽器及 API 驗證：一般決策送出前後捲動差 0 px；安全提醒插入後，原題的視窗座標差 0.390625 px。兩者均保留未送出的 SBAR 草稿。測試安全錯誤只發生於隔離測試學員，原始重作歷史保留。

## 同網路與 iPhone

登入入口：`https://192.168.68.108:8765/login`。主機 Wi-Fi IP 改變時，依啟動工具顯示的新網址與新憑證重新設定。

同一 TCP 8765 另提供 `http://192.168.68.108:8765/connect` 設定說明及公開 CA 安裝描述檔。HTTP 不接受登入 POST、不轉送資料 API；登入、資料與語音仍走 HTTPS。描述檔只含可移除的根憑證，沒有 MDM、帳號或私鑰。

使用者於 2026-10-24 直接回報 iPhone 已顯示連線診斷頁的主機版本，麥克風音量有變動。因此實機 HTTPS 可達與麥克風收音記為通過。**登入後的真人兩輪連續對話仍待實機結果，不能由合成音源測試代替。**

## 真人兩輪測試

用 iPhone Safari 登入既有學員帳號，進入 Step 4，展開「語音選項與自動驗證」，開啟「iPhone／真人兩輪語音測試」。按一次開始後，依畫面說：

1. 您好，請說明目前需要一起確認的資料。
2. 謝謝您的說明，還有哪些資訊需要再核對？

每句停頓後應自動送辨識，角色回覆播放完應自動繼續收音。報告明示 `physical-microphone` 或 `controlled-synthetic-audio`，避免混淆實體麥克風和合成測試。兩種診斷均不寫入正式對話、決策或能力分數。Safari 若阻擋播放，會提示按播放鍵，不能將需手動播放的結果當作完整連續互動通過。

本版另以實際瀏覽器完成兩輪 MediaRecorder → Whisper → gemma4:12b → 中文 TTS → 自動接續收音，約 75 秒，五種嘴型皆有觀測值。兩輪的文字相似度為 1.00 與 0.882；音源明示為合成語音，未使用 iPhone 實體麥克風。

另外以合成語音轉 AAC / MP4 後，已實際通過本機 faster-whisper 解碼及中文辨識；這項僅驗證 Safari 常用音訊編碼相容性。

## 2026-10-24 上午部署複查與修復

08:45 複查發現主程式已不在執行，8705 / 8765 無監聽；先前通過的紀錄不能代表當時仍在服務，原程序沒有留下完整的結束原因。已恢復主機，將啟動改為透過 Windows WMI 建立獨立隱藏程序，啟動工具需確認主程式版本符合才回報成功。記錄在 `runtime/lan-service.log` 及 `runtime/lan-host.json`。

已為目前 Windows 帳號加入登入啟動捷徑，指向 `tools/start_lan_background.py`。設定工具是 `tools/install_lan_startup.ps1`；尚未為了測試而將使用者登出。主機須保持開機、登入 Windows 且不休眠，才能提供同網路服務。

另發現既有 LiveKit 只綁定回環位址；已修正為區網節點 `192.168.68.108`。啟動工具會在要求 LAN 而既有設定仍是回環時重建正確設定，保留現有私有憑證；已正確設定的服務則直接沿用。語音服務也改為獨立隱藏程序。已完成兩個客戶端的雙向 RTC 合成音訊實傳，各端收到超過 140 音框，透過 7882–7982 範圍的 UDP 媒體連線；這不是 iPhone 實體對話測試。

嚴格驗證 CA 的 HTTPS 健康檢查、登入頁、連線診斷頁均回傳 200；未登入的角色資料回傳 401；HTTP 登入 POST 回傳 405。既有防火牆兩項規則均啟用。公開 GitHub 最新發行仍為 v5.5.0，本機正在執行 v5.5.1；沒有將本機後端描述為 GitHub Pages 上的服務。

## 驗證與限制

功能測試 101 項後端及 17 項前端通過；最終 13 位模型另核對 SHA256、骨架、嘴型與曲面髮型資產。

測試與證據保存在本機 `runtime/verification-5.5.1/`，包含區網 / iPhone 回報、決策位置、Safari 音訊編碼與測試日誌。正式資料庫於升級前已建立一致性備份 `runtime/backups/before-5.5.1.sqlite3`。公開包與乾淨程式交付排除 runtime、學員資料、私鑰及帳密。

Piper 中文聲音權重及 PostgreSQL 正式資料移轉仍未配置。本次沒有重新錄製操作影片；既有 v5.4.0 實錄屬歷史版本。
