# 第五版部署

GitHub提供程式碼與公開素材下載。GitHub Pages只能呈現靜態內容；FastAPI、SQLite、Ollama及登入服務需在獨立主機執行。

## Windows本機

雙擊根目錄 `run_windows.bat`，網址為 http://127.0.0.1:8705 。首次安裝仍依既有規則使用管理員user／1234，既有帳密保留。學員及教師由管理員建立。公開伺服器另用下方的強密碼設定，不能直接公開本機資料庫。

從GitHub取得程式碼後，先安裝Python套件，再取得公開執行素材：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe tools/fetch_release_assets.py
.\run_windows.bat
```

公開素材包含擬真人物、風格化模型、前端執行套件及衍生教學資料；不含帳號、資料庫、密碼、來源PDF/Excel、原始影片或360代理影片。教材管理者另行提供來源文件與影片。缺教材時介面明示缺少內容，不以其他病種影片替代。

## Linux持久化主機

先執行 `python tools/fetch_release_assets.py`。建立 `.env`，設定至少12字元且獨有的 `BOOTSTRAP_ADMIN_PASSWORD`。預設模型為gemma4:12b；主機需自行具備相應資源。

```sh
docker compose up -d --build
docker compose exec ollama ollama pull gemma4:12b
```

應用程式只對主機127.0.0.1:8705綁定。以既有HTTPS反向代理轉送至此埠，並保留 `COOKIE_SECURE=1`。若只在本機HTTP驗收，可暫設 `COOKIE_SECURE=0`；公開網址必須使用HTTPS及Secure Cookie。SQLite使用單一worker與持久化volume；避免多個容器各自持有不同資料庫。

可設定 `OLLAMA_URL`、`OLLAMA_MODEL`、`OLLAMA_API_KEY` 使用受保護的外部Ollama。Ollama埠不直接公開；後端會核對實際模型名稱，錯誤與劇本模式會分開標示。連線到 `/api/tags` 只代表模型可見，仍須以角色對話確認實際推論成功。

啟動後檢查 `/health`，再登入教師介面檢查AI服務並完成兩輪對話。新安裝的公開環境只有管理員帳號；學員及教師由管理員新增，沒有公開共用學員帳號。

本機已完成實際LLM與瀏覽器驗收；Docker Compose已通過設定解析。此機Docker Linux引擎未運行，因此尚無容器建置、HTTPS站台及雲端LLM連線的實測結果。Windows中文TTS／虛擬講師合成依賴Windows；Linux部署目前以文字互動及已存在的影片播放為主。

## 360素材與備份

將教材管理者提供的代理檔放入 `data/video360/` 並核對 `catalog.json` 雜湊。原始案例影片由 `VIDEO_LIBRARY_DIR` 指定；Compose映射 `deployment-media/`。公開素材下載工具不會下載實拍教學影片。

使用 `python manage.py backup <新備份檔名>` 備份資料庫；完整私有備份可使用 `tools/backup_bundle.py`，包含media、speech及virtual_lessons。不要上傳私有備份至公開GitHub。
