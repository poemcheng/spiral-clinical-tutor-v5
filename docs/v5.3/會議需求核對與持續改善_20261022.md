# 2026-10-22 會議需求核對與持續改善

本輪版本：v5.3.0。核對依據為 `1022.txt` 的十項需求、使用者在本對話的確認，以及既有 v5.0–v5.2 實作與驗收證據。較早的 2026-10-21 會議整理稿僅作背景；正式會議日期、出席人員與醫療端核定內容仍以正式紀錄為準。

2026-10-23補充修正已另列於[5.3.1逐格動作與互動修正版](逐格動作與互動修正版_20261023.md)：加入實際逐格骨架、動作意圖候選、困難互動、男女聲配對與完整操作影片。本頁保留v5.3.0當時的核對結果；最新狀態以該修正版及`requirements-ledger.json`為準。

## 已確認的需求優先順序

- 以 4.5.1 為基礎更新第五版；保留既有帳號、學習紀錄及舊版證據。
- 護理師第二位互動對象為物理治療師；五職種示範配對依使用者明確確認執行。
- 自評 Level 決定互動難度，累積學習 Level 決定教材解鎖；教師正式能力核定另存。因此不沿用早期整理稿「所有首次學員互動難度一律 Level 1」的建議。
- 人物須為真正立體網格與骨架，不能以平面螢幕冒充 3D 人物。
- 先完成模型及語音自動測試；實體麥克風驗收依使用者回覆留待後續。
- GitHub 為公開程式與下載入口；未取得雲端主機設定前，不宣稱完整雲端後端已部署。

## 本輪實際修正

教師監看頁原先只有訓練 JSON 可讀取逐格觀察，缺少明確的回饋操作。v5.3 補上：

1. 教師在「Level 5 · 逐格觀察與教師回饋」檢視時間、影格、視角、原始觀察及媒體版本。
2. 保存「已檢視」或「建議補充」與具體回饋，保留每次歷史及教師身分。
3. 回饋綁定原觀察 SHA256；新觀察另存影片識別、fps 與來源／代理影片雜湊。
4. 使用上一筆回饋 ID 檢查同時編輯衝突，防止較舊頁面覆蓋新回饋。
5. 學員可於影片學習頁及成果頁查看歷次回饋；不改寫原觀察，不自動改分或升等。
6. 舊紀錄缺少媒體雜湊時明示，仍可檢視與提供回饋；不補造歷史來源。

新增 `tools/check_meeting_requirements.py`：可重複核對 12 職類、五組配對、13 個模型、年齡／性別、四部影片版本及院徽來源。它明確分開「技術檢查通過」與「會議需求全部驗收」，不會把待教師或待部署項目自動結案。

## 驗證與資料範圍

本機 Python 64 項測試與前端 3 項測試通過。新增測試涵蓋回饋權限、歷史追加、版本快照、衝突檢查、完成後保留原始成果、舊資料相容，以及文字跳脫與回饋索引。

瀏覽器驗收使用獨立資料庫與合成帳號，從學員保存觀察、教師保存回饋到學員查看歷史逐段核對；不使用正式學員當作測試資料。執行證據保存在 `runtime/verification-5.3/`。本機教材雜湊核對可執行：

```sh
python tools/check_meeting_requirements.py --require-local-media
python -m unittest discover -s tests -q
npm run test:ui
```

公開程式碼安裝未附私人 VR360 時，使用不帶 `--require-local-media` 的檢查；缺少影片會如實標示，不會宣稱已檢查不存在的影片。
